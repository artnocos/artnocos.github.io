h2. *何をするもの？*

"セキュリティ用語解説 - NRIセキュアテクノロジーズ":https://www.nri-secure.co.jp/glossary/ctf より

{% quote  %}
CTF（Capture The Flag）とは、情報セキュリティの分野では、専門知識や技術を駆使して隠されているFlag（答え）を見つけ出し、時間内に獲得した合計点数を競うハッキングコンテストを指します。クイズ形式の問題を解くほか、ネットワーク内で疑似的な攻防戦も行ったりすることもあります。
{% endquote %}

"SECCON Beginners CTF 2026 競技ルール":https://www.seccon.jp/15/seccon_beginners/ctf.html

{% quote  %}
3. フラグのフォーマットは `ctf4b{[\x20-\x7e]+}` です。これと異なる形式を取る問題に関しては、別途問題文等でその旨を明示します。
{% endquote %}

つまり『通常は見えないようになっている文字列を探して回答しなさい、その文字列のフォーマットは正規表現で @ctf4b{[\x20-\x7e]+}@ になっていますよ』ということだ
（というのが最初は上記説明を読んでもピンと来なかった）

h2. *準備*

今回の参加にあたってはWSL2上のUbuntu24を使用した
問題の説明には @nc@ 等のコマンドが載っている、ダウンロードできるファイルにはDockerfileやPythonのスクリプトも含まれる
というわけでUNIX系のコマンドやコンテナが使える、なんらかの環境があったほうがいいだろう
最近の競技プログラミングはサイト側に用意された環境を使ってソースコードを入力するだけになってきているが、様々なツールを使いこなせる必要があるCTFは自分で環境を用意することになる
ASCII文字以外を端末から入力する方法も事前に確認しておくといい（私は去年やったことを完全に忘れていて、同じことをするRubyのフィルタプログラムを作り直した）

昨年の大会ではKali Linuxをインストールして使ってみたりもしたが、今回は使わなかった
普段から使っている環境でないとalias等の設定を全部やり直さないといけなくて不便だったので

昨年のリバースエンジニアリング系の問題では、最初はバイナリを逆アセンブルして解いたりもしたが、大会中のDiscordで逆コンパイルが可能なGhidraというツールがあることを知って、今年もそれを使った

h3. Ghidraのインストール

"GitHub - NationalSecurityAgency/ghidra: Ghidra is a software reverse engineering (SRE) framework":https://github.com/nationalsecurityagency/ghidra

"インストールの説明":https://github.com/nationalsecurityagency/ghidra#install を見ると2026年6月時点でインストール可能なGhidra 12.1.2をインストールするにはJDK 21が必要なようだ
@aptitude search jdk@ で見つけた @openjdk-21-jdk@ をインストールすることにする（jreでも動かせそうだが起動スクリプトでの指定がjdkになっていて、書き換えるのも面倒なのでjdkの方をインストールする）

説明に従ってrelease fileをダウンロード、起動スクリプト @ghidraRun@ を実行すると

{% quote %}
Exited with error.  Run in foreground (fg) mode for more details.
{% endquote %}

のようなエラーが出るが、環境変数 @DISPLAY@ を設定すればWSLgでも実行できる

{% highlight sh %}
export DISPLAY=:0
{% endhighlight %}

あとは適当にプロジェクトを作ってファイルをインポート、コードブラウザを開き、AnalyzeやFunctionsを選んでDecompileをする

h2. *参考URL（RSA暗号）*

RSAに関する問題を解くために参考にしたサイトのリンクを載せておく（もう一度リンクを探しなおさなくていいように）
でも今更RSAに詳しくなる必要もそれほど無い気はしている

# "RSA暗号を使ったやり取りの仕組み":https://it-trend.jp/encryption/article/64-0056#chapter-2
（もう一つ、"RSA暗号の鍵生成手順" が書かれた kobe-u.ac.jp のサイトを載せようとしたらHTTPSでなくて載せられなかった）
暗号などの数学が関係している文献、式を見るとき、記号の意味が分からないことがよくある
学校では習わなかったり、習ったものとは違う記号を使っていたり、あるいは単に忘れていたり、その度に「この記号なに？」と調べるが、記号は検索しにくくて手間がかかる
上記サイトは比較的記号が少なく読み易かった
三本線で表す「合同」は比較的よく見る記号なので覚えておいてもいいと思う、試しに「合同」で検索したら図形の話ばかり出てきて説明を見つけるのが難しかった
(mod n) の部分は、合同の計算を考える時の、割る数を明示している補足情報、と思えば読みやすいと思った
# "Python組み込み関数 pow()":https://docs.python.org/ja/3/library/functions.html#pow
RSAの秘密鍵である @d@ を求める計算は、モジュラ逆数というものを求めることにより行う
問題に付属するPythonのコードではこれを @pow()@ により求めていたりする
@pow()@ って累乗（べき乗）を求めるものじゃなかったっけ？と考えると意味が分からないのだが、第二引数に負数を指定するとべき乗の指数の意味ではなくなって @pow()@ がモジュラ逆数を求める関数に早変わりする（より正確には第三引数の指定と組み合わせた場合）
この指定方法の元ネタは数式から来ているようだが、第二引数と第三引数がフラグ引数になっていて、Pythonの @pow()@ は制御結合度が高い関数になっている
OpenSSLなどで使われているmod_inverseの方が分かりやすい

h2. *最後に*

セキュリティ関連の技術は研修などで知識としては知っているが、普段の開発では何がどこまで必要なのかよく分からなくなることがある
CTFで攻撃を体験すると、どのセキュリティ対策をしたほうがいいのかといった理解度が上がるように感じる

今回は参加登録時に「人間が主体」か「AIが主体」かを選んだ
去年はそのようなことは聞かれなかったと思う
最近は攻撃もAIで行われているようなので、攻撃もAI、対策もAI、な世界になってきているのかもしれない
AI同士が戦っているのを、人間は何も分からず横で眺めているだけ、というのも違う気がするので、来年も人間主体で参加してみるつもりだ
